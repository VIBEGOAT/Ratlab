e-Rat Virtual Lab

A simulated laboratory rat for drug testing, wound studies, circadian monitoring and memory tasks. Built to replace, reduce and refine the use of live animals.

How a study runs on e-Rat

The same six steps apply to every experiment type. Each step is logged with the seed and parameters, so any run can be repeated exactly.

  1. Define the study

    State the question, the endpoints (tumor volume, closure time, latency) and the protocol.

  2. Build a virtual cohort

    Pick strain, sex, age and condition. Each animal gets its own random biological variation.

  3. Apply the intervention

    Dose a drug, create a wound, shift the light cycle or set a maze task.

  4. Simulate

    Mechanistic engines run the cohort: pharmacokinetics, tissue repair, a circadian oscillator and a learning agent.

  5. Read out

    Group curves, effect sizes and uncertainty bands, the same way a lab report would show them.

  6. Validate and decide

    Compare with historical rat data. Only candidates that pass go on to a small, confirmatory live-animal study.

Replace

  • Early screening of dose, schedule and compound choice runs on virtual cohorts.
  • Pilot wound and behavior studies need no live animals.

Reduce

  • Simulation sets the group size before any live study, using the spread the model predicts.
  • Weak candidates are dropped in silico, so fewer reach animals.

Refine

  • Virtual dose-ranging finds the point where toxicity starts without harming a real animal.
  • Endpoints and humane stop rules are tested virtually first.

What this can and cannot claim

No model reproduces a rat at 100 percent. The goal is a model that predicts specific endpoints within a stated error, shown by testing against animal data the model never saw. Where that test is passed, the animal study can be skipped or shrunk. Where it is not, e-Rat says so and a live study is still needed. System blueprint

This page is the first layer of a larger platform. The table shows which model sits behind each experiment now and what replaces it as real data arrives.

1. Web labStudy designer, virtual cohort builder, result dashboards, exportable protocol and audit log. This prototype.
2. OrchestratorTakes a study definition, fans it out to the engines, collects results and records seed, versions and parameters for exact replay.
3. Model enginesPBPK and PD, tumor and infection growth, tissue repair, circadian oscillator, metabolism and feeding, learning agent. Each engine is swappable and versioned.
4. Virtual rat coreStrain, sex, age and condition templates with physiology (organ weights, blood flows, enzyme activity) and a random variation model for each animal.
5. Data and validationCurated rat datasets, calibration jobs, held-out tests, error reports. Nothing is marked usable for a given endpoint until it passes here.

Roadmap

  • Phase 0 Prototype with placeholder parameters (this page).
  • Phase 1 Calibrate one engine, for example PK, to public rat datasets.
  • Phase 2 Add organ-level physiology and immune response.
  • Phase 3 Train behavior agents on real tracking data.
  • Phase 4 Blind prospective test: predict a new study, then compare with the real result.
  • Phase 5 Agree the fit-for-purpose scope with regulators and ethics committees.

Validation rules

  • Hold out whole studies, not rows, when testing.
  • Report prediction intervals and how often reality falls inside them.
  • State a context of use for each engine, such as "rank compounds by exposure".
  • Show an uncertainty flag whenever a run leaves the calibrated range.

Suggested stack

  • Python with FastAPI for the orchestrator.
  • SciPy or Julia for ODE solvers. Open Systems Pharmacology tools for PBPK.
  • Gymnasium and PyTorch for behavior agents.
  • Postgres for runs and parameters, object storage for raw traces.
  • React front end, this page as the starting design.
